Überblick

Das Programm liest eine CSV-Datei Zeile für Zeile und sendet jede Zeile als eine MQTT-Nachricht an einen Broker – gedrosselt, damit Broker und Cloud nicht überlastet werden. Typischer Einsatz: Messdaten, die während eines Verbindungsausfalls lokal gespeichert wurden, nachträglich in die Cloud liefern.

  • Dateien mit mehreren 100'000 Zeilen werden gestreamt (geringer Speicherbedarf).
  • Senderate einstellbar (Standard 50 Nachrichten/s).
  • Bei Abbruch kann ab der letzten sicher gesendeten Zeile fortgesetzt werden.

Schnellstart

  1. Register Einstellungen: Host, Port, Benutzer/Passwort eintragen, bei Bedarf TLS aktivieren → Verbindung testen → Einstellungen speichern.
  2. Register Senden: CSV öffnen … (Ctrl+O). Hilfe jederzeit mit F1 oder den ?-Knöpfen.
  3. Im Bereich Zuordnung der Spalten prüfen, welche Spalte das Topic und welche die Payload ist. Die Spalten werden in der Vorschau-Tabelle farbig markiert.
  4. Das Feld Vorschau der ersten MQTT-Nachricht kontrollieren.
  5. Optional Prüflauf: prüft die ganze Datei, ohne zu senden.
  6. ▶ Senden starten und Rückfrage bestätigen.

CSV-Beispiele

A) Topic und Payload stehen fertig in der Datei

Häufigster Fall bei Exporten aus Node-RED / einer Offline-Queue:

timestamp;topic;payload
2026-10-01 12:00:00;d2c/TWA01/energy;{"u":26.3,"i":38}
2026-10-01 12:00:01;d2c/TWA02/energy;{"u":20.8,"i":49}

Zuordnung: Topic aus Spalte = topic, Payload aus Spalte = payload. Die Payload wird unverändert gesendet. Weitere Spalten (hier timestamp) werden ignoriert.

Enthält die Payload das Trennzeichen (z.B. , in JSON und , als CSV-Trenner), muss das Feld in Anführungszeichen stehen und innere " verdoppelt sein: "{""u"":26.3,""i"":38}". So exportieren Excel und die meisten Tools automatisch.

B) Messwerte in einzelnen Spalten

Zeitstempel;device;Spannung;Strom;Status
01.10.2026 00:00:00;TWA00;26,30;38;OK

Zuordnung: Topic Vorlage d2c/{device}/data, Payload JSON aus Spalten. Ergebnis:

Topic:   d2c/TWA00/data
Payload: {"Zeitstempel":1790805600000,"device":"TWA00","Spannung":26.3,"Strom":38,"Status":"OK"}

(mit Zeitstempel-Spalte = Zeitstempel, Dezimalkomma aktiv, Ausgabe Epoch ms)

Zuordnung der Spalten

Beim Öffnen einer Datei versucht das Programm die Spalten zu erraten (Namen wie topic, path, pfad bzw. payload, message, data). Die Auswahl wird gespeichert und beim nächsten Öffnen einer Datei mit gleichen Spaltennamen wieder verwendet.

Topic

OptionBedeutung
aus SpalteDer Text der gewählten Spalte ist das Topic. Mit Präfix kann etwas vorangestellt werden, z.B. Präfix d2c/ + Spalte TWA01/energy → d2c/TWA01/energy.
VorlageTopic wird zusammengesetzt. {Spaltenname} wird durch den Wert der Zeile ersetzt, {row} durch die Zeilennummer. Beispiel: d2c/{device}/data.

Leere Topics sowie Topics mit + oder # sind in MQTT nicht erlaubt – solche Zeilen werden übersprungen und im Log gemeldet.

Payload

OptionBedeutung
aus SpalteDer Text der Spalte wird unverändert als Payload gesendet. Mit muss gültiges JSON sein werden Zeilen mit ungültigem JSON übersprungen statt gesendet.
JSON aus SpaltenAus den angehakten Spalten wird ein JSON-Objekt gebaut (Spaltenname = Schlüssel). Optional wird eine Zeitstempel-Spalte umgewandelt. Weitere Optionen unter Einstellungen → JSON-Optionen.

In der Vorschau-Tabelle sind die Spalten markiert: [Topic], [Payload]; nicht angehakte JSON-Spalten erscheinen grau.

Senden & Fortschritt

ElementFunktion
Ab DatenzeileErste zu sendende Zeile (1 = erste Zeile nach der Kopfzeile).
AnzahlWie viele Zeilen gesendet werden. 0 = bis zum Dateiende. Praktisch für einen Test mit z.B. 10 Zeilen.
PrüflaufLiest die ganze Datei, baut alle Nachrichten, sendet aber nichts. Fehlerhafte Zeilen erscheinen im Log.
⏸ Pause / ▶ WeiterHält das Senden an; die Verbindung bleibt bestehen.
■ StoppBeendet das Senden. Der Fortsetzungspunkt wird gespeichert.
PositionBis zu dieser Zeile ist alles sicher gesendet (bei QoS 1/2: vom Broker bestätigt).
Bestätigt (offen)Vom Broker bestätigte Nachrichten; in Klammern noch unbestätigte.
ÜbersprungenZeilen, die nicht gesendet werden konnten (z.B. leeres Topic). Details im Log.
Rate / RestzeitAktuelle Senderate (gleitend über 5 s) und geschätzte Restdauer.

Dauer-Beispiel: 500'000 Zeilen bei 50/s ≈ 2 h 47 min.

Unterbruch & Fortsetzen

  • Verbindungsabbruch: Das Programm baut die Verbindung automatisch wieder auf und sendet unbestätigte Nachrichten erneut. Es geht nichts verloren.
  • Stopp, Absturz, PC-Neustart: Alle 2 s wird pro Datei gespeichert, bis wohin sicher gesendet wurde. Beim erneuten Öffnen erscheint Fortsetzen ab Zeile X → anklicken → Senden starten.
  • Der Fortsetzungspunkt gilt nur für dieselbe, unveränderte Datei (Pfad, Grösse, Änderungsdatum).
Bei QoS 1 gilt „mindestens einmal“: Nach einem Abbruch können einzelne Nachrichten doppelt in der Cloud ankommen. Die Empfangsseite sollte doppelte Datensätze (z.B. gleicher Zeitstempel) tolerieren.

Installation & Updates

Installieren

  1. Auf GitHub unter Releases die neueste Datei d2c_DataUpload_MQTT_…_win-x64.zip herunterladen.
  2. ZIP in einen eigenen Ordner entpacken, z.B. C:\Tools\d2c_DataUpload_MQTT.
  3. d2c_DataUpload_MQTT.exe starten. Keine Installation und keine Admin-Rechte nötig; .NET ist enthalten.
Erscheint die Windows-Meldung „Der Computer wurde durch Windows geschützt“: Weitere Informationen → Trotzdem ausführen. Das passiert bei Programmen ohne bekannte Signatur.

Updates

  • Beim Start fragt das Programm höchstens einmal täglich bei GitHub nach einer neueren Version (abschaltbar unter Einstellungen → Allgemein). Es werden dabei keine Daten übertragen.
  • Ist eine neue Version verfügbar, erscheint oben ein blauer Hinweis mit Herunterladen, Was ist neu und Diese Version überspringen.
  • Manuell: Menü Hilfe → Nach Updates suchen …
  • Aktualisieren: Programm schliessen, neue ZIP in denselben Ordner entpacken (Dateien ersetzen), neu starten. Einstellungen, Passwort und Fortsetzungspunkte bleiben erhalten (sie liegen nicht im Programmordner).
  • Nach dem ersten Start einer neuen Version zeigt der Hinweis einmalig Aktualisiert auf Version … mit Link zu den Neuerungen.

Senden

FeldBedeutung
QoS0 = höchstens einmal (schnell, ohne Bestätigung, Verlust möglich) · 1 = mindestens einmal (empfohlen) · 2 = genau einmal (langsamer).
RetainBroker speichert die letzte Nachricht pro Topic. Für Nachlieferungen normalerweise aus, sonst überschreiben alte Werte den aktuellen Retain-Wert.
Senderate (max.)Obergrenze Nachrichten pro Sekunde. Nach einer Pause wird nicht „nachgeholt“.
Max. unbestätigtSo viele Nachrichten dürfen gleichzeitig auf Bestätigung warten. Ist der Broker langsamer, bremst das Programm automatisch.

Dateien & Ordner

Alles liegt unter %APPDATA%\d2c_DataUpload_MQTT\ (Menü Hilfe → Einstellungsordner öffnen):

  • settings.json – Einstellungen, Zuordnung und Fortsetzungspunkte
  • logs\upload_JJJJMMTT.log – Log pro Tag

Die CSV-Datei selbst wird nie verändert. Einstellungen bleiben bei Updates erhalten.
