Overview

The program reads a CSV file row by row and sends each row as one MQTT message to a broker – rate-limited so that broker and cloud are not overloaded. Typical use: upload measurement data that was stored locally during a connection outage.

  • Files with several 100,000 rows are streamed (low memory use).
  • Adjustable send rate (default 50 messages/s).
  • After an interruption, sending resumes from the last safely sent row.

Quick start

  1. Settings tab: enter host, port, user/password, enable TLS if needed → Test connection → Save settings.
  2. Send tab: Open CSV … (Ctrl+O). Help is available any time with F1 or the ? buttons.
  3. In Column mapping, check which column is the topic and which is the payload. The columns are highlighted in the preview table.
  4. Check the field Preview of the first MQTT message.
  5. Optional Dry run: checks the whole file without sending.
  6. ▶ Start sending and confirm.

CSV examples

A) Topic and payload are ready in the file

Most common case for exports from Node-RED / an offline queue:

timestamp;topic;payload
2026-10-01 12:00:00;d2c/TWA01/energy;{"u":26.3,"i":38}
2026-10-01 12:00:01;d2c/TWA02/energy;{"u":20.8,"i":49}

Mapping: topic from column = topic, payload from column = payload. The payload is sent as is. Other columns (here timestamp) are ignored.

If the payload contains the delimiter (e.g. , in JSON and , as CSV delimiter), the field must be quoted and inner " doubled: "{""u"":26.3,""i"":38}". Excel and most tools export it this way automatically.

B) Measured values in separate columns

Zeitstempel;device;Spannung;Strom;Status
01.10.2026 00:00:00;TWA00;26,30;38;OK

Mapping: topic template d2c/{device}/data, payload JSON from columns. Result:

Topic:   d2c/TWA00/data
Payload: {"Zeitstempel":1790805600000,"device":"TWA00","Spannung":26.3,"Strom":38,"Status":"OK"}

(with timestamp column = Zeitstempel, decimal comma on, output epoch ms)

Column mapping

When a file is opened, the program tries to guess the columns (names like topic, path, pfad or payload, message, data). The selection is saved and reused for the next file with the same column names.

Topic

OptionMeaning
from columnThe text of the selected column is the topic. A prefix can be prepended, e.g. prefix d2c/ + column TWA01/energy → d2c/TWA01/energy.
TemplateThe topic is assembled. {column name} is replaced by the row's value, {row} by the row number. Example: d2c/{device}/data.

Empty topics and topics containing + or # are not allowed in MQTT – such rows are skipped and reported in the log.

Payload

OptionMeaning
from columnThe column text is sent unchanged as payload. With must be valid JSON, rows with invalid JSON are skipped instead of sent.
JSON from columnsA JSON object is built from the checked columns (column name = key). Optionally a timestamp column is converted. More options under Settings → JSON options.

The preview table marks the columns: [Topic], [Payload]; unchecked JSON columns are greyed out.

Interruption & resume

  • Connection loss: the program reconnects automatically and resends unacknowledged messages. Nothing is lost.
  • Stop, crash, PC restart: every 2 s the program saves per file how far it has sent safely. When the file is reopened, Resume from row X appears → click it → start sending.
  • The resume point only applies to the same, unchanged file (path, size, modification date).
QoS 1 means "at least once": after an interruption, single messages may arrive twice in the cloud. The receiving side should tolerate duplicate records (e.g. same timestamp).

Installation & updates

Install

  1. On GitHub under Releases, download the latest d2c_DataUpload_MQTT_…_win-x64.zip.
  2. Extract the ZIP into its own folder, e.g. C:\Tools\d2c_DataUpload_MQTT.
  3. Start d2c_DataUpload_MQTT.exe. No installation and no admin rights needed; .NET is included.
If Windows shows "Windows protected your PC": More info → Run anyway. This happens for programs without a known signature.

Updates

  • At startup the program asks GitHub for a newer version at most once a day (can be switched off under Settings → General). No data is sent.
  • If a new version is available, a blue notice appears at the top with Download, What's new and Skip this version.
  • Manually: menu Help → Check for updates …
  • To update: close the program, extract the new ZIP into the same folder (replace files), restart. Settings, password and resume points are kept (they are not stored in the program folder).
  • After the first start of a new version, the notice shows Updated to version … once, with a link to the changes.

Settings

Changes are applied with Save settings or when switching to the Send tab.

General

Check for new versions at startup: see Installation & updates.

Language: Deutsch or English. Can also be switched in the View → Language menu; the interface changes immediately. Help opens in the selected language.

MQTT broker

FieldMeaning
Host / PortBroker address. Usually 1883 (without TLS), 8883 (with TLS).
Client IDMust be unique on the broker. Two programs with the same ID disconnect each other.
User / PasswordLeave empty if the broker requires no login. The password is stored encrypted (Windows DPAPI): only the same Windows user on this PC can read it. After changing PC or user it must be entered again.
KeepaliveHeartbeat interval in seconds (default 60).
Use TLSEncrypted connection (mqtts).
CA certificateOnly needed for a private / company certificate authority. Empty = system certificate store.
Do not verify certificateTesting only! The connection is then not protected against eavesdropping.
Test connectionOpens a test connection and reports the result.

Send

FieldMeaning
QoS0 = at most once (fast, no acknowledgement, loss possible) · 1 = at least once (recommended) · 2 = exactly once (slower).
RetainThe broker keeps the last message per topic. For uploading history usually off, otherwise old values overwrite the current retained value.
Send rate (max.)Upper limit of messages per second. After a pause there is no catch-up burst.
Max. unacknowledgedHow many messages may wait for acknowledgement at the same time. If the broker is slower, the program slows down automatically.

Troubleshooting

MessageCause / solution
Connection refused (check port/host)No broker on that port, or a firewall blocks it.
Host name not foundTypo in host, no network, or VPN not connected.
No response from brokerUsually TLS mismatch: TLS port without the TLS checkbox or vice versa.
TLS certificate invalidCA certificate missing or wrong; host name does not match the certificate.
Connection rejected by broker: Not authorizedWrong user/password or no permission (ACL) for the topic.
Disconnected … reconnectingNetwork interruption or broker restart. The program reconnects itself. Frequent disconnects: the client ID is used twice.
Topic is empty / Payload is emptyEmpty cell in that row → row skipped.
Payload is not valid JSONOnly with option must be valid JSON. Often doubled "" exported incorrectly.
X columns instead of YRow has more fields than the header – usually a delimiter inside text without quotes.
Umlauts wrongSet encoding to windows-1252 and Reload.
Rate lower than configuredBroker acknowledges slowly (max. unacknowledged reached) or weak connection.

Files & folders

Everything is stored under %APPDATA%\d2c_DataUpload_MQTT\ (menu Help → Open settings folder):

  • settings.json – settings, mapping and resume points
  • logs\upload_YYYYMMDD.log – one log per day

The CSV file itself is never modified. Settings are kept across updates.
